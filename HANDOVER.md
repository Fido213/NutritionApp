## 1. Project at a glance

Local-first nutrition tracker (Android APK via Capacitor + web preview). Source of truth: **`Ai Guidelines/`** (master spec, governance rules, AI logs) + **`PLAN.md`** + the actual code.

```
UI events → services (food/ai/import/export/backup/transfer) → domain logic → repositories → SQLite
```

Core principle: **Gemma interprets. Code calculates. SQLite remembers.**

## 4. Known limitations (unchanged, documented in pass-3/pass-8 logs)

- **`webrtc-transport.ts` (P2P) is unverified** — no browser/device/`RTCPeerConnection` in this environment. The next browser/device pass must click through the full pairing → transfer → restore flow. **ICE configuration:** two public STUN servers by default (pass 10), plus an **optional TURN server field in the P2P modal** (Settings → Receive/Send Backup → "Optional: TURN server") persisted in localStorage (`everydayfuel_p2p_turn`), for pairing across different networks. Gathering no longer blocks on unreachable STUN (pass-10 follow-up: resolves after first candidates + 2s grace, hard cap 15s — fixes "Timed out gathering connection candidates"). No TURN by default — no cloud relay unless the user opts in; the backup payload is AES-GCM encrypted regardless.
- Fallback connection is a degraded shim — pass 10 closed the reported gaps (positional INSERTs, UPDATE, ORDER BY/LIMIT incl. standalone LIMIT, water GROUP BY, COUNT(*), ON CONFLICT + `excluded.*`, JOIN-foods enrichment, DELETE by id/combo_id are all implemented and covered by `database-shim.test.ts`). Unknown statement shapes still degrade to no-ops; `combo_items` filter support is partial (DELETE by combo_id only — combos' FK cascade `DELETE FROM combo_items WHERE combo_id = ?` is covered; other combo_item queries are not simulated). Restore (file or P2P) in fallback mode bypasses SQL and replaces the store wholesale (correct). The real-SQLite suite proves all repository SQL works on the real engine — the shim is the only degraded path.

- `btn-save-goals` still creates a new goal per save (pre-existing)
- Label-OCR fallback parser preserves the old-app regex (old_app/api/index.py): for kJ-first EU energy lines it captures the kJ value as `caloriesPer100g` — locked in by a regression test (gemma-client.test.ts), documented, not "fixed" because that would change preserved old-app behavior; revisit when wiring Phase 7.
